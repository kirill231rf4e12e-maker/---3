# Кейс-задача №3. Блог

> Учебное **web-приложение для ведения блога** с регистрацией и авторизацией пользователей, созданием и управлением публикациями, подписками, тегами и комментариями.

Приложение поддерживает **публичные и приватные публикации**, персональную ленту на основе подписок, поиск постов по тегам и просмотр профилей авторов.

> **Примечание:** в данном README подробно представлен весь реализованный функционал с наглядными примерами работы приложения.

---

# Запуск проекта

Для запуска приложения необходимо выполнить следующие шаги:

1. Создать базу данных с названием `the_blog`.
2. Импортировать структуру и исходные данные из файла `bd.sql`.
3. Открыть файл config.php и при необходимости указать параметры подключения к MySQL.
4. Поместить папку проекта в директорию htdocs / www локального сервера.
5. Запустить Apache и MySQL.
6. Открыть index.php в браузере.
7. Авторизоваться с помощью тестового аккаунта или зарегистрировать нового пользователя.

## Итог и Анализ выполненной задачи

В результате выполнения кейс-задачи была разработана **web-версия блога** с регистрацией и авторизацией пользователей, созданием публикаций, системой подписок, комментариями, тегами и поддержкой приватного контента.

1. Реализована полноценная система регистрации и авторизации пользователей. После входа пользователю становятся доступны основные функции приложения.

2. Реализовано создание, редактирование и удаление публикаций. При создании поста можно указать заголовок, содержание, теги и тип публикации.

3. Реализовано разделение публикаций на **публичные и приватные**. Для приватной публикации автоматически формируется уникальный код доступа, который используется для просмотра скрытого контента.

4. Реализована система подписок. Пользователь может подписываться на интересующих авторов, отменять подписку и просматривать персональную ленту публикаций.

5. Реализованы две основные ленты: публичная лента с доступными для общего просмотра публикациями и персональная лента на основе подписок.

6. Реализована система комментариев. Пользователь может добавлять комментарии к публикациям, а также изменять и удалять собственные комментарии.

7. Реализована работа с тегами. Пользователь может выполнять поиск публикаций по заданному тегу, при этом в результатах поиска отображаются только доступные публичные посты.

8. Реализованы пользовательские профили. В профиле автора отображаются его публичные публикации, а также доступны действия подписки и отписки.

9. Используется реляционная база данных для хранения информации о пользователях, публикациях, комментариях, тегах и подписках. Данные между основными сущностями связаны посредством структуры базы данных.

10. Для хранения паролей используется **хеширование**, благодаря чему учетные данные пользователей не сохраняются в базе данных в открытом виде.

11. Интерфейс приложения разделён на отдельные страницы для авторизации, регистрации, просмотра ленты, публикаций и профилей пользователей, что упрощает навигацию и работу с системой.

12. В README представлена подробная документация по реализованному функционалу и приведены наглядные примеры работы основных возможностей приложения.

## Выявленные ошибки и рекомендации

1. **Необходима защита POST-запросов от CSRF-атак.** Для всех форм изменения данных рекомендуется использовать CSRF-токены и проверять их на сервере.

2. **Следует усилить валидацию пользовательского ввода.** Необходимо установить ограничения на длину заголовков, содержания публикаций, тегов и комментариев, а также корректно обрабатывать некорректные значения.

3. **Рекомендуется добавить пагинацию лент.** При большом количестве публикаций загрузка всех записей на одной странице будет увеличивать время формирования страницы и объём передаваемых данных.

4. **Поиск по тегам можно расширить.** В дальнейшем можно добавить поиск сразу по нескольким тегам, поиск по заголовку публикации и дополнительные параметры фильтрации.

5. **Для приватных публикаций рекомендуется усилить механизм доступа.** Помимо уникального кода можно ограничить количество попыток ввода, установить срок действия ссылки или реализовать индивидуальные права доступа.

6. **Стоит добавить уведомления для пользователей.** Например, можно уведомлять пользователя о новых публикациях авторов, на которых он подписан, новых комментариях и других действиях, связанных с его аккаунтом.

7. **Рекомендуется добавить систему модерации.** Для полноценного блог-сервиса можно реализовать администратора или модератора, который сможет удалять нежелательный контент, блокировать пользователей и контролировать публикации.

8. **Необходимо предусмотреть защиту от повторной отправки форм.** После успешного создания публикации или комментария рекомендуется использовать паттерн Post/Redirect/Get, чтобы повторное обновление страницы не создавало дубликаты.

9. **Для масштабирования проекта можно улучшить структуру приложения.** Логику работы с базой данных, обработку запросов и отображение страниц рекомендуется разделить по отдельным компонентам или перейти к архитектуре MVC.

10. **Для реального использования проекта рекомендуется добавить журналирование действий и обработку ошибок.** Это позволит отслеживать проблемы приложения и контролировать действия пользователей.

11. **Следующим этапом развития проекта может стать добавление реакций на публикации.** Например, можно реализовать отметки «Нравится», счётчик просмотров и сортировку популярных публикаций.

12. **Перспективным улучшением является добавление полнотекстового поиска.** Это позволит искать публикации не только по тегам, но и по содержимому и заголовкам постов.
